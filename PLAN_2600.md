Chase the CPU cost until it is: gate Y = 0.60 passes/frame first, then as high as is cheap (target 0.75+). Double-speed X = 1.00. Order below = biggest expected win first. ### Stage 1b findings (2026-11-02)

**Result:** gates X and Y are both met on the three start levels measured. Steps 5-7 are left until the user's playtest says they matter; smooth edges stays parked.

**What is left in the peaks** (proxy, units): first-use atlas builds 140-160k in one pass (a few times per game), road rows 80-100k for ~10 passes at each bridge, exact-path tile jobs ~80k, a band replay ~150k. A pass over a frame now costs its own length, not a whole extra frame, but 150k is still 2 frames on screen.

**Pacing:** a pass ends by publishing scroll and a finished OAM page (`publish_pass`, page 2 at `$D000`, `_shadow_OAM_base`), and the VBlank handler shows the latest one. Sprites and scroll always come from the same pass, and tile data is written before the scroll that reveals it. HUD, palette and stripe writes may now land in active display: the library routines all wait on STAT (checked in the ROM's bytes) and the stripe loop does too.

**Tooling.** The profiler charges banked function bodies to `.call_hl` (they are entered with `jp hl`). `tests/gb/trace_prof.mjs` + `tools/trace_hist.py` replay a cycle-exact disk trace into per-phase and per-function cost, and agree with the profiler (`oam_camera` 17.7k against 18.3k). `-PassLog` now holds the pass log: it cost ~2k units per pass in every `-ProfExport` ROM, so earlier numbers read slightly high.

**The plan's estimate was wrong.** `bcall` is ~1% of the time, not 3.3-6.7k per call (that figure was inclusive of the callee). The 49k "entities+player" was entities 21k, player 4k, HUD 8k and more.

**Pass time is a step function:** `vsync()` always waits for the NEXT VBlank, so a pass of 71k units costs 140k. At the start of Stage 1b 28% of all time was idle while the median pass needed 80k: only 39% of passes fitted in a frame. Passes/frame follows the share of passes under 70k, so a 40% cut in work took the rate from 0.57 to 0.83.

Fast flight, proxy clock, level 1, units per pass (`trace_hist`), before -> after the first cuts:

**Proof (LESSONS 18):** `-OamCheck` compares every pass's hardware OAM with the C reference walk, redraws the entities through the C path with the old limit (`ent_check_redraw`) and compares again, and runs the player scan both ways: 1,500+ passes on start indexes 0-3, 0 errors. `-RiverCheck` runs every river row through the assembly and the C from the same state: 2,700 rows on the 2600 and exact rivers, 0 errors. Host golden diff against the previous commit (exact, features, blocky, fast x 4 start levels): identical at each river change. Skipped rows cannot appear before the next redraw: y <= 95 + 6 rows (`RIVER_MAX_OWED`) + 8 <= 112 (compile-time assert). The one intended difference: off-view rows no longer use up the 37-sprite entity budget.
