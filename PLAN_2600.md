## Stage 1 — 2600 river on GBC

### 0. Workspace (done 2026-11-02)
- [x] Branch `river-2600`; GBC docs moved to `archive/gbc/`; new HANDOFF, PROGRESS, BUGS&FEATS, this plan.

### 1. Scope the mod
- [ ] Byte-diff `xex/River Raid 2600.xex` against the original with `tools/dump_xex.py`. List the segments and which differ. The mod is 2,534 bytes larger, so expect new code or data, not only patched bytes.
- [ ] Disassemble the changed regions (`tools/disasm_stats.py`, `docs/atari_disasm_*.txt` for the original side). Name what each change does.
- [ ] Write `docs/MOD_2600_SPEC.md`: what changed in river generation, collision, enemies/spawns, sound, HUD. Mark anything that is not the river.
- [ ] Decide from the spec whether non-river changes pollute the capture (proposal risk 1).

### 2. Capture the mod's river
- [ ] Reuse `tools/atari_river_trace.py` / `tools/compare_river_edges.py` against the mod; follow the rules in `info/LESSONS.md` → "Reverse Engineering Tools". Sample across frames, not one read.
- [ ] Record edge slopes, segment lengths, per-level behaviour, island/bridge handling. Store raw captures under `assets/atari/extracted/` (new `river2600/` folder) with a README line.
- [ ] Confirm the edges come from a small set of slopes (this decides the atlas size; proposal row 9).

### 3. Baseline (exact river, current ROM)
- [ ] `.\build_gbc.ps1 -ProfExport`, then `tests/gb/run_emu.ps1 tests/gb/profile_play.mjs fast` and `cruise`. Record proposal rows 1-7 here.
- [ ] Name the player and entity groups in the profile (row 3) before recording.
- [ ] Build without `cpu_fast()` for row 8 (the DMG proxy) and record it.

### 4. Model
- [ ] Add a 2600 edge mode to `tools/river_model.py` (one edge description shared by collision and drawing).
- [ ] Extend `tests/host_river.ps1` to check both modes against the C generator.
- [ ] Compare the model against the captures from task 2.

### 5. C generator and atlas renderer
- [ ] `src/river.c`: second mode behind a compile-time flag (inside `#ifdef __SDCC_sm83` while GBC-only; NES RAM has ~3 bytes free).
- [ ] Atlas renderer: fixed edge tiles in VRAM, tilemap writes plus `SCY` only.
- [ ] After every link check each bank's `.map` window (`AGENTS.md` rule 8). Bank 0 had ~3 KB free at the start.
- [ ] Build both targets after touching shared files.

### 6. Measure and hand over
- [ ] Repeat the baseline runs with the 2600 mode; add row 9 (atlas tiles, tilemap writes per frame).
- [ ] Hand the user a playtest checklist. Stage 1 check is the user's call.
